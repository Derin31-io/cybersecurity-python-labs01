# Лабораторна робота №3 — Варіант 4: Облік подій автентифікації

## Опис проєкту

У межах лабораторної роботи реалізовано Web API для збереження та керування результатами спостереження за подіями автентифікації.

Застосунок використовує:

- **Python**;
- **FastAPI** для створення Web API;
- **SQLite** для збереження даних;
- **Pydantic** для перевірки вхідних даних;
- параметризовані SQL-запити для роботи з базою даних;
- транзакції для забезпечення цілісності пакетних операцій;
- **Ruff** для перевірки стилю та форматування коду.

## Предметна область

Сервіс призначений для збереження підсумків спостереження за автентифікацією.

Один запис описує кількість подій певного типу за навчальний інтервал.

### Основні параметри варіанта

| Параметр | Значення |
|---|---|
| Варіант | 4 |
| Предметна область | Облік подій автентифікації |
| Одиниця вимірювання | `events` |
| Тип значення | `int` |
| Мінімальне значення | `0` |
| Поріг реагування | `20 events` |
| Статуси | `new`, `in_progress`, `done` |

### Категорії

Для початкового набору даних використовуються три категорії:

- `failed_login` — невдалі спроби входу;
- `blocked_account` — блокування облікового запису;
- `mfa_failure` — помилки багатофакторної автентифікації.

```http
GET /categories
```

Приклад:


```http
POST /categories
```

## Робота із записами

### Отримання списку записів

```http
GET /records
```

Без фільтрів:

```bash
curl -i "http://127.0.0.1:8000/records"
```

### Фільтрація за категорією

```bash
curl -i "http://127.0.0.1:8000/records?category_id=1"
```

### Фільтрація за статусом

```bash
curl -i "http://127.0.0.1:8000/records?status=new"
```

### Фільтрація за мінімальною кількістю подій

Для варіанта 4 параметр `min_value` має відповідати значенню `events`:

```bash
curl -i "http://127.0.0.1:8000/records?min_value=20"
```

### Пошук за назвою

```bash
curl -i "http://127.0.0.1:8000/records?q=автентифікації"
```

### Пагінація

```bash
curl -i "http://127.0.0.1:8000/records?limit=5&offset=0"
```

Параметри:

- `limit` — кількість записів у відповіді;
- `offset` — кількість пропущених записів.

### Комбінування фільтрів

```bash
curl -i "http://127.0.0.1:8000/records?category_id=1&status=new&min_value=20&limit=5&offset=0"
```

Якщо задано декілька фільтрів, вони застосовуються одночасно.

## Отримання одного запису

```http
GET /records/{record_id}
```

Приклад:

```bash
curl -i "http://127.0.0.1:8000/records/1"
```

У відповіді повертається інформація про запис разом із назвою категорії.

## Створення запису

```http
POST /records
```

Приклад для варіанта 4:

```bash
curl -i -X POST "http://127.0.0.1:8000/records" \
  -H "Content-Type: application/json" \
  -d '{
    "code": "V04-TEST",
    "title": "Інтервал автентифікації TEST",
    "category_id": 1,
    "value": 25,
    "status": "new"
  }'
```

Поле `value` для варіанта 4:

- має бути цілим числом;
- не може бути меншим за `0`;
- дробові значення, наприклад `1.5`, є некоректними.

Успішне створення повертає `201 Created`.

## Оновлення запису

Для повної заміни змінюваних полів використовується:

```http
PUT /records/{record_id}
```

Приклад:

```bash
curl -i -X PUT "http://127.0.0.1:8000/records/1" \
  -H "Content-Type: application/json" \
  -d '{
    "code": "V04-01",
    "title": "Оновлений інтервал автентифікації",
    "category_id": 1,
    "value": 30,
    "status": "in_progress"
  }'
```

`id` запису не передається в тілі запиту та залишається незмінним.

## Видалення запису

```http
DELETE /records/{record_id}
```

Приклад:

```bash
curl -i -X DELETE "http://127.0.0.1:8000/records/1"
```

У разі успіху повертається:

```text
204 No Content
```

## Пакетне створення записів

Для одночасного додавання декількох записів використовується:

```http
POST /records/bulk
```

Приклад:

```bash
curl -i -X POST "http://127.0.0.1:8000/records/bulk" \
  -H "Content-Type: application/json" \
  -d '[
    {
      "code": "V04-BULK-01",
      "title": "Пакетний запис 01",
      "category_id": 1,
      "value": 10,
      "status": "new"
    },
    {
      "code": "V04-BULK-02",
      "title": "Пакетний запис 02",
      "category_id": 2,
      "value": 25,
      "status": "in_progress"
    }
  ]'
```

Усі записи пакета зберігаються в межах однієї транзакції.

Якщо один із записів містить помилку, наприклад дубльований `code` або неіснуючий `category_id`, весь пакет скасовується.

Таким чином, не допускається ситуація, коли перший запис зберігся, а наступний завершився помилкою.

## Коди HTTP

Основні коди, які використовує API:

| Код | Значення |
|---|---|
| `200 OK` | Успішне отримання або оновлення |
| `201 Created` | Успішне створення |
| `204 No Content` | Успішне видалення |
| `404 Not Found` | Запис або категорію не знайдено |
| `409 Conflict` | Дублікат унікального значення або конфлікт видалення |
| `422 Unprocessable Entity` | Некоректні вхідні дані |
| `500 Internal Server Error` | Неочікувана помилка сервера |

## Валідація даних

Для перевірки вхідних даних використовуються Pydantic-моделі.

Перевіряються:

- довжина текстових полів;
- відсутність зайвих полів;
- додатність ідентифікаторів;
- тип та допустимий діапазон `value`;
- допустимий статус;
- наявність необхідної категорії;
- параметри пагінації.

Для варіанта 4 `value` є цілим числом `>= 0`.

Допустимі значення `status`:

```text
new
in_progress
done
```

## База даних

У проєкті використовується SQLite без ORM.

База містить дві таблиці:

```text
categories
    |
    | 1:N
    |
records
```

Таблиця `categories` містить категорії.

Таблиця `records` містить результати спостережень та має зовнішній ключ `category_id`, який посилається на `categories.id`.

Для підтримання цілісності даних використовуються:

- `PRIMARY KEY`;
- `FOREIGN KEY`;
- `UNIQUE`;
- `NOT NULL`;
- `CHECK`;
- `ON DELETE RESTRICT`.

SQL-запити виконуються з параметрами, а не шляхом конкатенації введених користувачем значень.

## Перевірка транзакцій

Для перевірки атомарності пакетної операції необхідно виконати запит, у якому один запис є коректним, а інший містить конфлікт, наприклад вже існуючий `code`.

Очікуваний результат:

```text
409 Conflict
```

При цьому коректний запис із цього самого пакета також не повинен з'явитися в базі.
